# meep-gpu certification reference, Apple silicon (osx-arm64): the conda part.
# The conda environment on the Apple M1 Max in which the Metal kernels were certified,
# restricted to the packages the reference needs. MEEP 1.33.0 is built from source on
# top of it (parity/meep_gpu/build_meep_133_macos.sh); the PyPI packages come from
# meep-gpu-ref-osx-arm64.pip.txt. README.md in this directory says how it was made.
#
# 127 of these 138 artifacts are the ones the certified environment installed (same URL,
# same MD5). The other 11:
#   hdf5, h5py  the mpi_openmpi builds. The certified environment holds the nompi build
#               of hdf5 1.14.6 (build 106; this is build 6) and the PyPI wheel of h5py
#               3.14.0. With a nompi HDF5, multi-rank MEEP output deadlocks.
#   9 packages the build needs and the certified environment lacks: the C++ driver of
#               its compiler build (clangxx_impl_osx-arm64), the compiler activation
#               packages (clang_osx-arm64, clangxx_osx-arm64, gcc_osx-arm64,
#               gfortran_osx-arm64, sdkroot_env_osx-arm64), the libc++ headers that match
#               its libc++ runtime (libcxx-headers, libcxx-devel), and make.
# openblas 0.3.30 (openmp_hea878ba_4) is the certified environment's own artifact: it adds
# lib/libopenblas.dylib, which MEEP's configure links as BLAS_LIBS = -lopenblas, as in
# the certified build.
#
# Installed without a solve, so conda checks neither dependencies nor the host; the
# packages need macOS 11.0 or later:
#   conda create -p <prefix> --no-default-packages --file meep-gpu-ref-osx-arm64.conda.txt
# platform: osx-arm64
